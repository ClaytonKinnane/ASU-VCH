# Правила разработки

## Ветки

- `main` содержит стабильное состояние проекта.
- Новая функциональность разрабатывается в ветках `feature/...`.
- Исправления выполняются в ветках `bugfix/...`.
- Слияние в `main` выполняется через Pull Request после проверки.

## Коммиты

Используется понятный префикс назначения изменения:

- `feat:` — новая функциональность;
- `fix:` — исправление;
- `style:` — оформление;
- `docs:` — документация;
- `refactor:` — переработка без изменения назначения;
- `chore:` — служебные изменения.

## Ограничения

- Не добавлять сторонние зависимости без предварительного согласования.
- Не хранить секреты, пароли и локальные настройки в Git.
- Не вносить несогласованные архитектурные решения.
- Изменения должны соответствовать PHP 8.3+, разработка ведется под PHP 8.5.
