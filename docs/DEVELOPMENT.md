# Правила разработки

## Источник истины

Репозиторий `ClaytonKinnane/ASU-VCH` на GitHub является единственным источником истины для кода и документации проекта.

Архитектурные решения сначала обсуждаются и утверждаются. Несогласованные архитектурные изменения не вносятся.

## Ветки

- `main` содержит стабильное состояние проекта.
- Новая функциональность разрабатывается в ветках `feature/...`.
- Исправления выполняются в ветках `bugfix/...`.
- Слияние в `main` выполняется через Pull Request после проверки.
- Текущая рабочая ветка начального сайта: `feature/initial-site`.

## Локальный тестовый клон

Полный тестовый клон располагается в:

```text
C:\Project\ASU-VCH
```

Он используется только для:

- получения изменений из GitHub;
- просмотра полученной версии;
- выполнения команд Git;
- запуска сценария `deploy\Deploy-Local.ps1`;
- локальной проверки в Open Server Panel.

Ручная разработка и редактирование файлов в тестовом клоне не выполняются. Локальные изменения из этого клона не должны отправляться в GitHub.

Перед тестированием необходимо получить актуальное состояние согласованной feature-ветки:

```powershell
Set-Location -LiteralPath 'C:\Project\ASU-VCH'
git status
git switch feature/initial-site
git pull --ff-only origin feature/initial-site
```

Рабочее дерево перед обновлением и развертыванием должно быть чистым.

## Разделение клона и веб-сервера

Клон репозитория не является корнем веб-сервера. Локальное тестовое развертывание выполняется в:

```text
C:\OSPanel\home\asu-vch.local
```

Apache обслуживает только:

```text
C:\OSPanel\home\asu-vch.local\public
```

Копирование выполняется исключительно утвержденным сценарием развертывания. Существующий проект `C:\OSPanel\home\asu.local` не изменяется.

## Коммиты

Используется понятный префикс назначения изменения:

- `feat:` — новая функциональность;
- `fix:` — исправление;
- `style:` — оформление;
- `docs:` — документация;
- `refactor:` — переработка без изменения назначения;
- `chore:` — служебные изменения.

## Ограничения

- Не добавлять сторонние зависимости без предварительного согласования.
- Не хранить секреты, пароли и локальные настройки в Git.
- Не вносить несогласованные архитектурные решения.
- Не использовать полный локальный клон как `web_root` Open Server Panel.
- Не копировать весь репозиторий в каталог веб-сервера.
- Изменения должны соответствовать PHP 8.3+, разработка ведется под PHP 8.5.
- Локальные команды и сценарии должны быть совместимы с Windows PowerShell 5.1.
