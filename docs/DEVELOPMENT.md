# Правила разработки

## Источник истины

Репозиторий `ClaytonKinnane/ASU-VCH` на GitHub является единственным источником истины для кода и документации проекта.

Изменения исходников и документации выполняются на GitHub в отдельной ветке. Локальный тестовый клон не используется для разработки, создания commit или push.

## Обязательный процесс

Материальный инкремент проходит этапы:

```text
Research
→ Analysis
→ Architecture
→ Specification
→ Review
→ Approval
→ Implementation
→ Testing
→ Commit
→ Push
→ Pull Request
→ Merge
```

Нельзя переходить к реализации нового инкремента без утверждённой документации и явного Approval владельца проекта.

Merge выполняется только после:

- завершения реализации;
- автоматического тестирования в целевой среде;
- требуемой пользовательской приёмки;
- Formal Review;
- отдельного явного разрешения владельца проекта.

## Ветки

- `main` содержит стабильное объединённое состояние проекта.
- Новая функциональность разрабатывается в `feature/...`.
- Исправления выполняются в `bugfix/...` или в активной feature-ветке, когда PR ещё не объединён.
- Документационные обновления выполняются в `docs/...`.
- Feature-ветки после merge сохраняются и не удаляются без отдельного разрешения.
- Конкретная рабочая ветка определяется текущим утверждённым инкрементом; постоянной feature-ветки проекта нет.

## Локальный тестовый клон

```text
C:\Project\ASU-VCH
```

Клон используется только для:

- `git fetch` и получения утверждённой ветки или `main`;
- проверки чистоты рабочего дерева и SHA;
- локального deploy в Open Server Panel;
- применения миграций;
- PHP lint, CLI checker'ов и HTTP/browser-проверок.

Перед синхронизацией рабочее дерево должно быть чистым. Для стабильной версии:

```powershell
Set-Location -LiteralPath 'C:\Project\ASU-VCH'
git status --short
git fetch --prune origin
git switch main
git pull --ff-only origin main
```

Для тестирования активного инкремента вместо `main` используется точное имя утверждённой ветки и ожидаемый remote HEAD.

Локально запрещены:

- ручное редактирование исходников и документации;
- `git add`, `git commit` и `git push` для проектных изменений;
- копирование файлов через Проводник;
- раскрытие `config/local.php` и секретов.

## Разделение репозитория и web root

```text
Git-клон:      C:\Project\ASU-VCH
Deploy root:   C:\OSPanel\home\asu-vch.local
Apache root:   C:\OSPanel\home\asu-vch.local\public
```

Deploy выполняется только контролируемым PowerShell-сценарием или согласованным проверочным скриптом. `config/local.php` должен сохраняться. Перед миграцией, изменяющей схему или данные, создаётся SQL backup.

## Коммиты

Используются понятные префиксы:

- `feat:` — новая функциональность;
- `fix:` — исправление;
- `style:` — оформление;
- `docs:` — документация;
- `refactor:` — переработка без изменения назначения;
- `test:` — проверки;
- `chore:` — служебные изменения.

## Технологические ограничения

- Windows PowerShell 5.1;
- PHP 8.5.4 в целевой среде, код не должен использовать возможности новее согласованной версии;
- MySQL 8.4.8;
- сторонние зависимости добавляются только после обоснования и Approval;
- секреты, пароли и локальные параметры не хранятся в Git;
- архитектурные решения не вводятся скрыто в коде или миграции;
- мобильная версия не объявляется проверенной без фактической мобильной приёмки.
