# Локальный запуск стартовой версии АСУ-ВЧ

## 1. Назначение

Этот документ описывает первый воспроизводимый запуск приложения в Open Server Panel на Windows PowerShell 5.1.

Утвержденные пути:

```text
Репозиторий: C:\Project\ASU-VCH
Развернутое приложение: C:\OSPanel\home\asu-vch.local
Адрес: https://asu-vch.local
```

## 2. Предварительные условия

Должны быть установлены и доступны:

- Open Server Panel 6.5.1;
- Apache;
- PHP 8.5;
- MySQL 8.4;
- PowerShell 5.1;
- полный Git-клон проекта.

Перед началом необходимо перейти в репозиторий и обновить ветку:

```powershell
Set-Location C:\Project\ASU-VCH
git switch feature/initial-site
git pull
```

## 3. Настройка подключения к БД

При первом развертывании файл создается автоматически из примера:

```text
C:\OSPanel\home\asu-vch.local\config\local.php
```

Проверьте в нем:

```php
'database' => [
    'host' => '127.0.0.1',
    'port' => 3306,
    'name' => 'asu_vch',
    'username' => 'root',
    'password' => '',
    'charset' => 'utf8mb4',
],
```

Файл `config/local.php` не должен попадать в Git.

## 4. Основной сценарий: пустая production-подобная установка

Запустите:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\Initialize-Local.ps1
```

Сценарий последовательно:

1. находит PHP 8.5;
2. выполняет `php -l` для всех PHP-файлов;
3. развертывает проект в Open Server Panel;
4. сохраняет существующий `config/local.php` при повторном развертывании;
5. создает БД и применяет миграции;
6. создает роль `system_owner`;
7. создает разрешение `system.*.*`;
8. оставляет таблицу пользователей пустой;
9. оставляет первичную регистрацию доступной.

После выполнения перечитайте конфигурацию проектов или перезапустите Open Server Panel.

Откройте:

```text
https://asu-vch.local
```

Зарегистрируйте первого владельца. После успешного создания владельца регистрация должна автоматически отключиться.

## 5. Альтернативный локальный сценарий с тестовым владельцем

Для быстрого локального тестирования допускается создать временного владельца:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\Initialize-Local.ps1 -SeedLocalOwner
```

Учетная запись:

```text
Admin
12315
```

Этот режим разрешен только при `environment=local`. Он не является production-bootstrap.

## 6. Повторный запуск без копирования файлов

Когда приложение уже развернуто, а требуется только повторно выполнить проверку и установщик:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\Initialize-Local.ps1 -SkipDeploy
```

## 7. HTTP smoke-тест

После запуска Apache, PHP и MySQL выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\Test-LocalSmoke.ps1
```

При локальном недоверенном сертификате:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\Test-LocalSmoke.ps1 -AllowInvalidCertificate
```

Проверяются:

- `/` возвращает HTTP 200;
- `/health.php` возвращает HTTP 200;
- `/admin/` для анонимного пользователя возвращает HTTP 302;
- `health.php` возвращает `status=ok`;
- подключение к БД имеет состояние `connected`.

## 8. Ручной приемочный тест

### Без пользователей

1. Открывается форма регистрации первого владельца.
2. Форма входа не является основным доступным действием до завершения установки.
3. Создание первого владельца завершается успешно.
4. Пользователь получает роль `system_owner`.
5. Роль имеет разрешение `system.*.*`.
6. Пользователь автоматически входит в систему.
7. Открывается `/admin/`.
8. Повторное обращение к регистрации отклоняется сервером.

### После завершения установки

1. Главная страница показывает форму входа.
2. Вход с корректными данными открывает `/admin/`.
3. Панель показывает плитки `Контент`, `Пользователи`, `Настройки системы`.
4. Раздел `Пользователи` показывает реальные счетчики.
5. Раздел `Настройки системы` показывает реальные диагностические сведения.
6. Выход уничтожает сессию.
7. Анонимный запрос к `/admin/` перенаправляется на `/`.

## 9. Фиксация результата

При ошибке сохраните:

- команду, которая была запущена;
- полный текст ошибки;
- версию PHP;
- версию MySQL;
- содержимое ответа `/health.php` без секретов;
- соответствующую запись из журналов Apache/PHP.

Успешный локальный прогон является обязательным условием перед началом реализации интерфейса управления пользователями, ролями и разрешениями.
