## Документы инкрементов

Для каждого функционального инкремента используются каталоги:

```text
docs/design/       Architecture, Specification, Review, Addendum, PR Final Review
docs/decisions/    Approval и зафиксированные решения
docs/testing/      Test Report и доказательства проверки
```

Эти файлы являются историческими артефактами процесса и фиксируют состояние на момент соответствующего этапа. Формулировки `PENDING`, `Ready for review` или `Merge prohibited` внутри закрытого отчёта отражают тогдашний gate и не заменяют текущий статус проекта.

Текущий lifecycle всех завершённых инкрементов ведётся в [PROJECT-STATUS.md](PROJECT-STATUS.md), а результаты проверки документации — в [DOCUMENTATION-AUDIT-2026-07-27.md](DOCUMENTATION-AUDIT-2026-07-27.md).

## Правила актуальности

1. GitHub-репозиторий является единственным источником истины.
2. Актуальные документы не должны ссылаться на завершённую feature-ветку как на текущую рабочую ветку.
3. Текущие возможности должны подтверждаться merged-кодом, миграциями и результатами тестирования.
4. Исторические спецификации не переписываются задним числом; при изменении решения создаётся addendum или новый документ.
5. Секреты, реальные пароли и содержимое `config/local.php` в документацию не включаются.
6. Мобильное тестирование не объявляется выполненным, если оно было исключено из scope.
