# Минимальная стартовая версия: база данных и панель администратора

## 1. Статус документа

- Этап: Specification
- Ветка: `feature/initial-site`
- Назначение: завершить минимальную стартовую версию сайта до продолжения проектирования бизнес-доменов.

## 2. Цель

Реализовать минимальный сквозной сценарий:

1. локальная база данных MySQL;
2. вход существующего пользователя;
3. защищенная сессия;
4. переход в панель администратора;
5. отображение стартовых блоков настройки и управления;
6. выход из системы;
7. локальная проверка в Open Server Panel.

Решение должно учитывать уже утвержденные архитектурные правила Security, Reference, Audit, Organization и общие архитектурные паттерны, но не обязано реализовывать все замороженные домены в полном объеме.

## 3. Границы стартовой версии

### Входит

- подключение PHP-приложения к MySQL через PDO;
- минимальная миграция Security;
- таблицы `users`, `roles`, `permissions`, `user_roles`, `role_permissions`;
- системная роль `system_owner`;
- разрешение `system.*.*`, обозначающее полный доступ стартового владельца системы;
- временный пользователь `Admin` с паролем `12315`;
- хранение пароля только как результата `password_hash()`;
- серверная авторизация;
- PHP-сессия;
- CSRF-защита форм входа и выхода;
- главная страница панели администратора;
- диагностические блоки панели;
- сценарий установки/обновления минимальной БД;
- обновление сценария локального развертывания;
- инструкция локальной проверки.

### Не входит

- публичная регистрация;
- восстановление пароля;
- управление пользователями через интерфейс;
- полноценный редактор ролей и разрешений;
- реализация Organization, Documents, Orders и других бизнес-доменов;
- полноценный Audit;
- production-развертывание;
- постоянное использование тестового пароля.

## 4. Временный пользователь

Стартовые учетные данные:

```text
Username: Admin
Password: 12315
Role: system_owner
Access: absolute test access
```

Правила:

- имя пользователя при поиске канонизируется в нижний регистр;
- отображаемое имя может оставаться `Admin`;
- пароль никогда не хранится в открытом виде;
- seed идемпотентен;
- повторный запуск установки восстанавливает требуемую тестовую роль и разрешение;
- учетная запись явно помечается как временная;
- перед production-этапом пользователь должен быть удален либо пароль должен быть заменен.

Низкая сложность пароля допускается только для изолированной локальной стартовой версии по прямому решению владельца проекта.

## 5. Минимальная модель данных

### `users`

- `id BIGINT UNSIGNED AUTO_INCREMENT`
- `username VARCHAR(100)`
- `username_canonical VARCHAR(100)`
- `email VARCHAR(255) NULL`
- `email_canonical VARCHAR(255) NULL`
- `password_hash VARCHAR(255)`
- `display_name VARCHAR(150)`
- `is_active BOOLEAN`
- `is_temporary BOOLEAN`
- `must_change_password BOOLEAN`
- `last_login_at DATETIME NULL`
- `created_at DATETIME`
- `updated_at DATETIME`
- `deleted_at DATETIME NULL`

Ограничения:

- уникальный `username_canonical` без повторного использования после soft delete;
- уникальный nullable `email_canonical` без повторного использования после soft delete;
- публичная регистрация отсутствует.

### `roles`

- `id BIGINT UNSIGNED AUTO_INCREMENT`
- `code VARCHAR(100)`
- `name VARCHAR(150)`
- `description VARCHAR(500) NULL`
- `is_system BOOLEAN`
- `created_at DATETIME`
- `updated_at DATETIME`

### `permissions`

- `id BIGINT UNSIGNED AUTO_INCREMENT`
- `code VARCHAR(150)`
- `name VARCHAR(150)`
- `description VARCHAR(500) NULL`
- `is_system BOOLEAN`
- `created_at DATETIME`
- `updated_at DATETIME`

### `user_roles`

- `user_id BIGINT UNSIGNED`
- `role_id BIGINT UNSIGNED`
- `assigned_at DATETIME`

### `role_permissions`

- `role_id BIGINT UNSIGNED`
- `permission_id BIGINT UNSIGNED`
- `assigned_at DATETIME`

Все внешние ключи используют `ON DELETE RESTRICT ON UPDATE RESTRICT`.

## 6. Конфигурация

Непубличная конфигурация приложения располагается вне `public`.

Целевая структура развертывания:

```text
C:\OSPanel\home\asu-vch.local\
├── app\
├── config\
├── database\
├── storage\
└── public\
```

Локальные параметры БД читаются из файла:

```text
config/local.php
```

Файл с реальными локальными учетными данными не коммитится. В репозитории хранится `config/local.example.php`.

Рекомендуемая локальная БД:

```text
Database: asu_vch
Host: 127.0.0.1
Port: 3306
Charset: utf8mb4
```

## 7. Авторизация

Маршруты стартовой версии:

```text
GET  /                  форма входа
POST /login.php         вход
GET  /admin/            панель администратора
POST /logout.php        выход
GET  /health.php        техническая проверка приложения и БД
```

Правила:

- публичная вкладка регистрации удаляется;
- при успешном входе выполняется `session_regenerate_id(true)`;
- неактивный или soft-deleted пользователь войти не может;
- пароль проверяется через `password_verify()`;
- запросы выполняются подготовленными выражениями PDO;
- при выходе сессия уничтожается;
- административная страница недоступна без аутентификации и роли `system_owner`;
- сообщения об ошибке входа не раскрывают, существует ли пользователь.

## 8. Главная страница панели администратора

Панель должна сохранить визуальный язык темы `asu-blue` и содержать следующие блоки.

### Рабочие блоки стартовой версии

1. **Сводка системы**
   - состояние PHP;
   - состояние подключения к MySQL;
   - имя БД;
   - время сервера;
   - версия приложения.

2. **Учетная запись**
   - отображаемое имя;
   - username;
   - роль;
   - время последнего входа;
   - предупреждение о временной учетной записи.

3. **Безопасность и доступ**
   - количество пользователей;
   - количество ролей;
   - количество разрешений;
   - ссылка-заглушка на будущее управление.

4. **Настройки системы**
   - режим окружения;
   - активная тема;
   - часовой пояс;
   - состояние debug;

5. **База данных**
   - состояние соединения;
   - количество примененных миграций;
   - дата последней миграции;

### Навигационные блоки с отметкой «в разработке»

- Пользователи;
- Роли и права;
- Справочники;
- Организационная структура;
- Документы;
- Аудит;
- Темы оформления;
- Обслуживание системы.

Неработающие действия не должны имитировать завершенный функционал. Они отображаются как отключенные либо явно помеченные «В разработке».

## 9. Миграции и seed

Сценарий:

```text
database/install.php
```

должен:

1. создать БД при наличии соответствующих полномочий либо подключиться к существующей;
2. создать таблицу `migrations`;
3. применить минимальную миграцию;
4. создать системную роль и разрешение;
5. создать или восстановить временного пользователя Admin;
6. вывести проверяемый итог без раскрытия password hash;
7. завершаться ненулевым кодом при ошибке.

Установка запускается только из CLI.

## 10. Локальное развертывание

`deploy/Deploy-Local.ps1` дополнительно копирует:

```text
app\      -> C:\OSPanel\home\asu-vch.local\app
config\   -> C:\OSPanel\home\asu-vch.local\config
database\ -> C:\OSPanel\home\asu-vch.local\database
```

Локальный `config/local.php` должен сохраняться при повторном развертывании либо автоматически создаваться из example-файла только при отсутствии.

Сценарий не должен копировать локальные секреты обратно в репозиторий.

## 11. Проверка

Минимальная приемка:

1. миграция выполняется без ошибок;
2. повторная миграция идемпотентна;
3. `/health.php` сообщает успешное подключение к БД;
4. неверный пароль отклоняется;
5. `Admin / 12315` выполняет вход;
6. после входа открывается `/admin/`;
7. анонимный запрос к `/admin/` перенаправляется на `/`;
8. панель показывает реальные счетчики БД;
9. выход уничтожает сессию;
10. после выхода `/admin/` снова недоступен;
11. в репозитории отсутствует открытый пароль и локальный конфигурационный файл;
12. PHP-файлы проходят `php -l`.

## 12. Ограничение проверки

GitHub является источником истины, однако фактическая проверка в `C:\OSPanel` должна выполняться на локальной машине владельца проекта после `git pull` и развертывания. Результат локального прогона фиксируется отдельно до признания стартовой версии завершенной.

## 13. Критерий завершения

Стартовая версия считается завершенной только после:

```text
Specification approved
Implementation completed
Static checks passed
Local Open Server test passed
Test credentials verified
Documentation updated
Commit and push completed
```

После этого проект возвращается к основной доменной работе, начиная с ранее отложенного домена Orders.
