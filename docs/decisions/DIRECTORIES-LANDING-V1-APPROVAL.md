# Стартовая страница справочников v1 — Approval

## Решение

Заказчик утвердил область инкремента `Стартовая страница справочников v1` и разрешил переход к реализации после Architecture / Specification / Review.

Точная команда заказчика:

> «Утверждаю область инкремента»

## Утверждённый scope

- активная плитка `Справочники` на `/admin/content.php`;
- новая owner-only страница `/admin/directories.php`;
- две статичные плитки: `Подразделения` и `Воинские звания`;
- статус `В разработке` для обеих плиток;
- кнопка `К контенту`;
- использование существующих компонентов обеих тем;
- повторное использование существующего hover-контракта `dashboard-tile` для активной плитки;
- автоматические структурные и syntax checks;
- отдельная desktop-визуальная приёмка пользователем.

## Уточнение по результатам приёмки

Первая desktop/runtime-проверка выявила два несоответствия принятому интерфейсу и критериям тестирования:

1. не-владелец перенаправлялся на панель вместо тематического HTTP 403;
2. на активной плитке `Справочники` отсутствовало действие `Открыть →`.

Заказчик зафиксировал оба замечания в ходе приёмки. Исправления признаны частью уже утверждённого scope, поскольку:

- тематический 403 был указан в критериях приёмки;
- `Открыть →` выравнивает активную плитку с существующей плиткой `Темы оформления`;
- новые permissions, роли, CSS-компоненты и предметная функциональность не добавляются.

Утверждённая корректировка:

- использовать существующий owner wildcard через `require_permission('system.*.*')` на `/admin/directories.php`;
- добавить `<span class="tile-action">Открыть →</span>` в активную плитку `Справочники`.

## Ограничения

Не входят:

- БД, migration и данные;
- CRUD;
- поиск, фильтрация и сортировка;
- новые permissions и изменение RBAC;
- мобильное тестирование;
- merge без отдельного явного разрешения.
