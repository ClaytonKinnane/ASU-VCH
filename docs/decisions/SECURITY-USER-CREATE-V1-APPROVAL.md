# Approval — Security / User Create v1

Статус: **Approved**  
Основной дизайн: `docs/design/SECURITY-USER-CREATE-V1-DESIGN.md`  
Дополнение: `docs/design/SECURITY-USER-CREATE-V1-AUDIT-METADATA-ADDENDUM.md`  
Миграция: `docs/design/SECURITY-MIGRATION-003-DESIGN.md`

## Утверждено

1. Создание выполняется через `/admin/users/create.php`.
2. Требуется разрешение `security.users.create`.
3. Для назначения ролей требуется `security.users.assign_roles`.
4. Новая учетная запись создается как `pending` и `is_active = 0`.
5. До подтверждения вход запрещен независимо от назначенных ролей.
6. Обязательные поля: логин, отображаемое имя, временный пароль, подтверждение пароля и основание добавления.
7. Основание содержит от 10 до 500 символов и сохраняется в `creation_reason`.
8. Автор создания сохраняется в `created_by`.
9. Временная учетная запись и обязательная смена пароля включены по умолчанию.
10. Минимальная длина пароля — 10 символов; обязательны буква и цифра.
11. Допускается создание без роли с предупреждением.
12. `administrator` может назначать `administrator`, `operator`, `viewer`.
13. `system_owner` может назначить только действующий владелец.
14. Создание пользователя и назначение ролей выполняются одной транзакцией.
15. Подтверждение выполняется отдельным POST-действием с CSRF и разрешением `security.users.update`.
16. Создатель может самостоятельно подтвердить созданную учетную запись при наличии требуемого разрешения.
17. При подтверждении сохраняются `approved_by` и `approved_at`.
18. Карточка пользователя должна показывать автора, дату создания, основание, подтвердившего и дату подтверждения.
19. Пароль не возвращается в HTML после ошибки и никогда не журналируется.

## Разрешение на реализацию

Разрешено реализовать:

- `app/Security/UserCreateService.php`;
- `app/Security/UserApprovalService.php`;
- регистрацию сервисов в `app/bootstrap.php`;
- `/admin/users/create.php`;
- `/admin/users/approve.php`;
- изменения списка пользователей и его репозитория;
- стили формы и статусов;
- CLI-проверки создания и подтверждения;
- последующую карточку пользователя отдельным инкрементом, если объем реализации потребует разделения.
