# Approval — Security / Users Management v1.0

Дата утверждения: **2026-07-24**  
Статус: **Approved**  
Домен: **Security**  
Основная спецификация: `docs/specifications/SECURITY-USERS-MANAGEMENT-V1.md`

## 1. Решение

Спецификация **Security / Users Management v1.0** утверждена для реализации с решениями, зафиксированными ниже.

## 2. Утвержденные решения

### 2.1 Назначение роли administrator

Пользователь с ролью `administrator` и разрешением `security.users.assign_roles` может назначать и снимать роль `administrator` другим пользователям.

Ограничения системного владельца продолжают действовать независимо от этого разрешения.

### 2.2 Управление ролью system_owner

Назначать и снимать роль `system_owner` может только пользователь, который сам имеет активную роль `system_owner`.

`administrator` не может:

- назначать `system_owner`;
- снимать `system_owner`;
- изменять или удалять системную роль `system_owner`;
- изменять или удалять разрешение `system.*.*`.

Операция не должна оставлять систему без активного владельца.

### 2.3 Восстановление архивированной учетной записи

Восстановление архивированных учетных записей входит в версию 1.0.

Восстановление:

- очищает `deleted_at`;
- не восстанавливает пароль из истории;
- не меняет роли автоматически;
- не активирует учетную запись автоматически, если она была заблокирована до архивирования;
- выполняется только через POST с CSRF-защитой и серверной проверкой разрешения.

Для операции используется разрешение:

```text
security.users.restore
```

### 2.4 Пагинация

Список пользователей получает серверную пагинацию сразу.

Параметры первой версии:

- размер страницы по умолчанию — 25;
- допустимые размеры — 25, 50, 100;
- некорректный номер страницы нормализуется сервером;
- поиск и фильтры применяются до подсчета страниц;
- параметры поиска, фильтра и размера страницы сохраняются в ссылках пагинации.

### 2.5 Поля, доступные viewer

Роль `viewer` не видит email и дату последнего входа других пользователей.

Для базового списка с разрешением `security.users.view` доступны:

- логин;
- отображаемое имя;
- вычисляемое состояние учетной записи;
- назначенные роли без административных действий.

Email и `last_login_at` доступны владельцу и администратору в рамках административного интерфейса. При последующем расширении политики видимости для них могут быть введены отдельные разрешения.

## 3. Дополнение каталога разрешений

К каталогу Security v1.0 добавляется:

```text
security.users.restore
```

Роль `administrator` получает это разрешение. Роль `system_owner` получает его через `system.*.*`.

## 4. Обновленные критерии приемки

Помимо критериев основной спецификации должны быть подтверждены следующие сценарии:

1. `administrator` может назначить другому пользователю роль `administrator`.
2. `administrator` не может назначить или снять `system_owner`, включая прямой POST-запрос.
3. `system_owner` может назначить второго владельца.
4. Нельзя снять роль у последнего активного владельца.
5. Архивированную учетную запись можно восстановить.
6. Восстановление не обходит прежнюю блокировку учетной записи.
7. Список выводится страницами по 25 записей по умолчанию.
8. Поиск и фильтры корректно работают совместно с пагинацией.
9. Пользователь только с ролью `viewer` не получает email и `last_login_at` ни в HTML, ни через прямой запрос к административному маршруту.

## 5. Разрешение на следующий этап

Разрешена подготовка детального дизайна и реализация миграции:

```text
002_security_users_management.sql
```

Реализация должна следовать основной спецификации и настоящему решению. Любое изменение утвержденных правил требует нового review и отдельного решения.
