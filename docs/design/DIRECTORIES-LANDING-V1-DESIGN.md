# Стартовая страница справочников v1 — Architecture / Specification

## 1. Статус документа

- Проект: `АСУ-ВЧ`
- Инкремент: `Стартовая страница справочников v1`
- Ветка: `feature/directories-landing`
- База: `main @ dce36c371b3eb6ef8a1365b24972660c0e62dd54`
- Статус: утверждено заказчиком; уточнено по результатам desktop-приёмки
- Дата утверждения: `2026-07-27`
- Дата корректировки: `2026-07-27`

## 2. Цель

Добавить owner-only точку входа в раздел справочников и стартовую страницу с двумя будущими справочниками:

1. `Подразделения`;
2. `Воинские звания`.

Инкремент создаёт только навигационную и визуальную основу. Хранение и управление данными не реализуются.

## 3. Архитектура навигации

```text
/admin/
  → /admin/content.php
      → /admin/directories.php
```

- существующая плитка `Справочники` на странице контента становится ссылкой;
- новая страница использует существующий PHP bootstrap;
- owner-only boundary страницы справочников реализуется через существующий `require_permission('system.*.*')`;
- wildcard `system.*.*` уже принадлежит владельцу системы и не создаёт нового permission;
- не-владелец получает существующую тематическую страницу с HTTP 403;
- возврат выполняется кнопкой `К контенту` на `/admin/content.php`;
- новые маршруты mutation отсутствуют.

## 4. Страница контента

Файл:

```text
public/admin/content.php
```

Изменения:

- плитка `Справочники` выводится как `<a>` с `href="/admin/directories.php"`;
- плитка содержит нижнее действие `Открыть →` через существующий класс `tile-action`;
- остальные восемь модулей остаются статичными `<article>` со статусом `В разработке`;
- информационный текст уточняется: вложенные модули вводятся поэтапно.

## 5. Страница справочников

Новый файл:

```text
public/admin/directories.php
```

Требования:

- `declare(strict_types=1)`;
- подключение `app/bootstrap.php`;
- owner-only boundary через `require_permission('system.*.*')`;
- тематический HTTP 403 для аутентифицированного не-владельца;
- заголовок страницы и документа: `Справочники`;
- описание: `Системные и предметные классификаторы`;
- кнопка `К контенту`;
- intro-блок с указанием, что управление данными появится в следующих инкрементах;
- `module-grid` с двумя плитками.

### 5.1 Подразделения

- заголовок: `Подразделения`;
- описание: `Справочник подразделений воинской части.`;
- статус: `В разработке`;
- не является ссылкой.

### 5.2 Воинские звания

- заголовок: `Воинские звания`;
- описание: `Справочник воинских званий военнослужащих.`;
- статус: `В разработке`;
- не является ссылкой.

## 6. Визуальный контракт

Используются существующие классы:

```text
site-header
container
header-content
site-logo
site-heading
site-title
site-description
secondary-button
admin-main
section-intro
glass-tile
module-grid
module-tile
dashboard-tile
tile-action
is-disabled
status-badge
```

Активная ссылочная плитка `Справочники` использует композицию существующих классов `dashboard-tile module-tile glass-tile`. Класс `dashboard-tile` предоставляет ссылочное поведение, transition и hover-свечение в обеих темах, а расположенный ниже контракт `module-tile` сохраняет компактный размер плитки модуля.

В нижней части активной плитки обязательно выводится `Открыть →` с классом `tile-action`, как в других доступных модулях системы.

Статичные плитки используют только `module-tile glass-tile is-disabled`, не получают `href` и не получают интерактивный hover.

## 7. RBAC и безопасность

- доступ наследует существующую owner-only модель раздела `Контент`;
- новая страница проверяет существующий wildcard владельца `system.*.*`;
- `AuthorizationService::hasPermission()` разрешает wildcard только пользователю, которому он назначен;
- не-владельцы получают существующую тематическую страницу 403 через `require_permission()`;
- новые permissions не добавляются;
- количество permissions остаётся `19`;
- CSRF не требуется, поскольку mutations и формы отсутствуют;
- пользовательские данные в разметку не добавляются, кроме существующего экранированного `display_name`.

## 9. Исключения из scope

Не входят:

- таблицы БД и migration;
- начальное наполнение;
- страницы списков;
- CRUD;
- поиск, фильтрация и сортировка;
- новые permissions и изменение ролей;
- аудит операций со справочниками;
- мобильное тестирование.

Нельзя заявлять, что мобильная версия проверена.

## 10. Критерии приёмки

1. `/admin/content.php` содержит активную плитку `Справочники`.
2. Активная плитка содержит нижнее действие `Открыть →`.
3. Переход ведёт на `/admin/directories.php`.
4. Новая страница открывается владельцу системы.
5. Администратор, оператор и наблюдатель получают тематический HTTP 403 без redirect на панель.
6. На странице ровно две справочные плитки.
7. Обе плитки имеют статус `В разработке` и не являются ссылками.
8. Кнопка `К контенту` возвращает на `/admin/content.php`.
9. Активная плитка контента использует существующий hover `dashboard-tile` в обеих темах.
10. Статичные плитки не поднимаются и не светятся.
11. PHP syntax checks проходят.
12. Desktop-визуальная приёмка обеих тем выполняется пользователем отдельно.
