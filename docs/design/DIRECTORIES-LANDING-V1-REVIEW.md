## 2. Architecture review

### 2.1 Размещение раздела

Справочники относятся к существующему owner-only разделу `Контент`. Вложенный маршрут `/admin/directories.php` не дублирует панель и сохраняет понятную иерархию.

Статус: **PASS**.

### 2.2 Boundary

Первоначальная реализация использовала `require_system_owner()`. Runtime-проверка показала, что этот guard перенаправляет не-владельца, поэтому не выполняет утверждённое требование тематического HTTP 403.

Корректировка использует существующий `require_permission('system.*.*')`:

- wildcard `system.*.*` уже назначен владельцу;
- `AuthorizationService::hasPermission()` поддерживает этот wildcard;
- новые permissions и изменения ролей отсутствуют;
- существующий `require_permission()` формирует тематическую страницу и HTTP 403.

Статус: **PASS AFTER CORRECTION; RUNTIME RETEST REQUIRED**.

### 2.3 Отсутствие преждевременной модели данных

На этом этапе не зафиксированы поля, иерархия, уникальность, архивирование или связи справочников. Отказ от migration и CRUD предотвращает преждевременное закрепление предметной модели.

Статус: **PASS**.

## 3. UI review

### 3.1 Повторное использование компонентов

Страница использует существующие header, intro, module grid и glass tile. Новый визуальный компонент не создаётся.

Статус: **PASS**.

### 3.2 Интерактивная плитка

Композиция `dashboard-tile module-tile glass-tile` повторно использует принятый hover-контракт обеих тем без изменения CSS. Статичные `<article>` не содержат `dashboard-tile` и остаются неинтерактивными.

Статус: **PASS**.

### 3.3 Действие активной плитки

Первая desktop-приёмка выявила отсутствие принятой нижней подписи действия. Плитка дополнена элементом:

```html
<span class="tile-action">Открыть →</span>
```

Используется существующий компонент, как у плитки `Темы оформления`; новый CSS не требуется.

Статус: **PASS AFTER CORRECTION; DESKTOP RETEST REQUIRED**.

### 3.4 Статусы

Обе будущие справочные плитки имеют `В разработке`, `is-disabled` и не содержат ссылок. Это соответствует принятому поведению статичных плиток.

Статус: **PASS**.

## 4. Security / RBAC review

- route mutation отсутствует;
- CSRF не применяется к read-only странице;
- `display_name` выводится через `e()`;
- direct access защищён server-side permission guard;
- владельцу разрешает существующий wildcard `system.*.*`;
- аутентифицированному не-владельцу возвращается тематический HTTP 403;
- новые permissions отсутствуют;
- permission count остаётся `19`.

Статус: **PASS WITH RUNTIME RETEST CONDITION**.

## 5. Scope review

Исправления не расширяют область:

- `Открыть →` является недостающим состоянием существующей активной плитки;
- тематический 403 уже был критерием приёмки;
- БД, CRUD, новые роли и permissions не добавляются;
- мобильное тестирование не включается.

Статус: **PASS**.

## 6. Проверки реализации

Обязательны:

1. PHP lint изменённых PHP-файлов.

6. Проверка hover активной плитки и статичности двух справочных плиток.
7. Проверка отсутствия migration и permission-изменений.
