# Справочник составов военнослужащих и воинских званий v1 — Architecture / Specification

## 1. Статус документа

- Проект: `АСУ-ВЧ`
- Инкремент: `Справочник составов военнослужащих и воинских званий v1`
- Ветка: `feature/military-ranks-directory`
- База: `main @ 89a7da6428d17b792a958c75fe636a90ae15dcb8`
- Статус: утверждено заказчиком
- Дата утверждения: `2026-07-27`

## 2. Цель

Добавить нормативный read-only справочник, объединяющий:

1. составы военнослужащих;
2. войсковые воинские звания;
3. соответствующие корабельные воинские звания;
4. нормативную последовательность старшинства;
5. официальные нормативные источники и дату проверки актуальности.

Плитка `Воинские звания` на странице справочников переименовывается в `Составы военнослужащих и воинские звания` и становится активной.

## 3. Нормативная основа

Первичное наполнение формируется по:

- Федеральному закону от 28.03.1998 № 53-ФЗ `О воинской обязанности и военной службе`, статья 46;
- Указу Президента Российской Федерации от 16.09.1999 № 1237 `Вопросы прохождения военной службы`, Положение о порядке прохождения военной службы, статья 20.

Официальные источники:

```text
https://www.kremlin.ru/acts/bank/12128/print
https://www.kremlin.ru/acts/bank/14416/print
```

Дата нормативной проверки для версии v1: `2026-07-27`.

По результатам проверки:

- нормативная пара для звания `сержант` — `старшина 1 статьи`;
- соответствующие друг другу войсковые и корабельные звания считаются равными;
- старшинство определяется последовательностью перечисления;
- `Маршал Российской Федерации` не имеет корабельного соответствия.

Пользовательский Word-документ используется как исходный материал для сопоставления, но не как нормативный источник.

## 4. Архитектурные принципы

### 4.1 Нормативность

Данные справочника нельзя изменять как обычные пользовательские записи. Любое будущее изменение должно быть связано с новым нормативным основанием и новой версией каталога.

### 4.2 Версионирование целиком

Каждая нормативная редакция хранится как отдельная версия каталога. При появлении изменений:

- создаётся новая версия;
- предыдущая версия закрывается датой окончания действия;
- исторические строки не удаляются;
- текущей считается ровно одна версия на уровне бизнес-логики.

### 4.3 Read-only v1

В v1 отсутствуют:

- POST-маршруты;
- формы изменения данных;
- создание, редактирование и удаление;
- ручное изменение нормативного порядка.

### 4.4 Нормативный порядок

`sort_order` в таблице уровней является юридически значимой нормативной последовательностью, а не произвольной сортировкой интерфейса.

### 4.5 Разделение базового звания и модификаторов

Не создаются отдельные записи для форм с добавлениями:

- `гвардии`;
- `юстиции`;
- `медицинской службы`;
- `запаса`;
- `в отставке`.

Эти атрибуты будут моделироваться позднее на уровне конкретного военнослужащего и правил формирования полного наименования.

## 5. Схема данных

Добавляется migration:

```text
database/migrations/007_military_ranks_directory.sql
```

### 5.1 `legal_sources`

Общий реестр нормативных источников:

- `id BIGINT UNSIGNED`;
- `code VARCHAR(120)` — стабильный технический код;
- `document_type VARCHAR(100)`;
- `document_date DATE`;
- `document_number VARCHAR(100)`;
- `title VARCHAR(500)`;
- `provision VARCHAR(150)`;
- `official_url VARCHAR(1000)`;
- `verified_at DATE`;
- `created_at DATETIME`.

Ограничения:

- PK `id`;
- UNIQUE `code`;
- UNIQUE по виду, дате, номеру и положению документа.

### 5.2 `military_rank_catalog_versions`

Версии справочника:

- `id BIGINT UNSIGNED`;
- `code VARCHAR(120)`;
- `name VARCHAR(255)`;
- `is_current BOOLEAN`;
- `valid_from DATE`;
- `valid_to DATE NULL`;
- `verified_at DATE`;
- `created_by BIGINT UNSIGNED NULL`;
- `created_at DATETIME`.

`created_by` ссылается на `users.id` с `ON DELETE SET NULL`. Для migration первоначальная версия создаётся с `created_by = NULL`.

### 5.3 `military_rank_catalog_version_sources`

Связь версии и нормативных источников:

- `catalog_version_id`;
- `legal_source_id`;
- `source_role`;
- `sort_order`.

Первичный ключ — пара версии и источника.

Роли источников v1:

- `primary-list` — статья 46 Федерального закона № 53-ФЗ;
- `equivalence-and-order` — статья 20 Положения, утверждённого Указом № 1237.

### 5.4 `military_personnel_compositions`

Иерархия составов:

- `id BIGINT UNSIGNED`;
- `catalog_version_id BIGINT UNSIGNED`;
- `parent_id BIGINT UNSIGNED NULL`;
- `code VARCHAR(100)`;
- `name VARCHAR(255)`;
- `sort_order SMALLINT UNSIGNED`;
- `created_at DATETIME`.

Создаются шесть узлов:

```text
Солдаты, матросы, сержанты, старшины
Прапорщики и мичманы
Офицеры
├── Младшие офицеры
├── Старшие офицеры
└── Высшие офицеры
```

Композитные внешние ключи должны исключать связь уровня или дочернего состава с другой версией каталога.

### 5.5 `military_rank_levels`

Нормативные уровни званий:

- `id BIGINT UNSIGNED`;
- `catalog_version_id BIGINT UNSIGNED`;
- `composition_id BIGINT UNSIGNED`;
- `code VARCHAR(100)`;
- `troop_name VARCHAR(255)`;
- `naval_name VARCHAR(255) NULL`;
- `sort_order SMALLINT UNSIGNED`;
- `created_at DATETIME`.

Ограничения:

- UNIQUE `(catalog_version_id, code)`;
- UNIQUE `(catalog_version_id, sort_order)`;
- состав и уровень должны принадлежать одной версии;
- `sort_order > 0`.

## 6. Первичное наполнение

### 6.1 Нормативные источники

Создаются две записи:

1. `federal-law-53-fz-article-46`;
2. `presidential-decree-1237-article-20`.

### 6.2 Версия каталога

```text
code: rf-military-ranks-2026-07-27
name: Составы военнослужащих и воинские звания Российской Федерации
is_current: 1
valid_from: 2026-07-27
valid_to: NULL
verified_at: 2026-07-27
```

`valid_from` обозначает начало использования данной проверенной версии в АСУ-ВЧ, а не дату первоначального вступления закона в силу.

## 7. Серверные компоненты

Добавляется:

```text
app/Directory/MilitaryRankCatalogRepository.php
```

Ответственность:

- найти текущую версию каталога;
- загрузить источники версии;
- вернуть составы в нормативном порядке;
- вернуть 20 уровней в нормативном порядке;
- выполнить read-only поиск по войсковому и корабельному наименованию;
- отфильтровать по составу;
- при выборе родительского состава `Офицеры` включить все дочерние офицерские составы.

В `app/bootstrap.php` добавляются подключение класса и factory-функция `military_rank_catalog_repository()`.

## 8. Маршруты и RBAC

Новая страница:

```text
/admin/directories/military-ranks.php
```

Навигация:

```text
/admin/
  → /admin/content.php
      → /admin/directories.php
          → /admin/directories/military-ranks.php
```

Boundary:

```php
require_permission('system.*.*');
```

Результат:

- владелец получает доступ через существующий wildcard;
- администратор, оператор и наблюдатель получают тематическую HTTP 403;
- новые permissions отсутствуют;
- количество permissions остаётся 19.

## 9. Плитка на странице справочников

Файл:

- применяется существующий интерактивный hover-контракт.

## 10. Интерфейс страницы

Страница включает:

1. header с полным названием и кнопкой `К справочникам`;
2. read-only информационный блок;
3. сведения о текущей версии и дате проверки;
4. две карточки нормативных источников с официальными ссылками;
5. поиск;
6. фильтр по составу;
7. кнопку применения фильтров;
8. кнопку сброса при активных фильтрах;
9. таблицу результатов.

Колонки таблицы:

```text
№
Состав военнослужащих
Войсковое звание
Корабельное звание
```

Для отсутствующего корабельного звания выводится `—`.

GET-параметры:

- `q` — строка поиска длиной не более 150 символов;
- `composition` — код существующего состава или пустое значение.

Некорректное значение фильтра сбрасывается в `all`.

## 12. Проверочный инструмент

Добавляется CLI checker:

```text
tools/check-military-ranks-directory.php
```

Он должен проверить:

- регистрацию migration 007;
- наличие пяти таблиц;
- количество источников, версий, составов и уровней;
- ровно одну текущую версию;
- нормативный порядок 1–20 без разрывов;
- все 20 пар наименований;
- `сержант — старшина 1 статьи`;
- `Маршал Российской Федерации — NULL`;
- связи с нормативными источниками;
- repository search и фильтрацию;
- сохранение количества системных permissions = 19.

Checker не изменяет данные.

## 14. Исключения из scope

Не входят:

- управление нормативными строками через UI;
- присвоение званий военнослужащим;
- история карьерного роста;
- первые и очередные звания;
- сроки нахождения в звании;
- представления и приказы;
- досрочное присвоение;
- гвардейские, юридические, медицинские и статусные модификаторы;
- интеграция со штатными должностями;
- мобильное тестирование.

## 15. Критерии приёмки

1. Migration 007 успешно применяется к существующей БД.
2. Повторный install сообщает, что новых миграций нет.
3. Созданы 2 источника, 1 текущая версия, 6 составов и 20 уровней.
4. Все пары и порядок соответствуют нормативным источникам.
5. Плитка переименована, активна и содержит `Открыть →`.
6. Владелец открывает страницу.
7. Остальные роли получают тематическую HTTP 403.
8. Поиск по обоим видам наименований работает.
9. Фильтр по составам, включая родительский состав `Офицеры`, работает.
10. Изменение данных через интерфейс невозможно.
11. PHP syntax checks проходят.
12. CLI checker проходит.
13. Существующие RBAC regression checks проходят.
14. Desktop-приёмка обеих тем проходит.
15. Мобильное тестирование не заявляется.
