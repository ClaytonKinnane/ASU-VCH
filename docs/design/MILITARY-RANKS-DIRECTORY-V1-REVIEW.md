# Справочник составов военнослужащих и воинских званий v1 — Formal Review

## 1. Объект review

Проверен документ:

```text
docs/design/MILITARY-RANKS-DIRECTORY-V1-DESIGN.md
```

База:

```text
main @ 89a7da6428d17b792a958c75fe636a90ae15dcb8
feature/military-ranks-directory
```

## 2. Нормативный review

### 2.1 Первичный источник перечня

Статья 46 Федерального закона № 53-ФЗ является достаточным первичным основанием для перечня составов и воинских званий.

Статус: **PASS**.

### 2.2 Равенство соответствующих званий и старшинство

Статья 20 Положения, утверждённого Указом № 1237, подтверждает соответствие войсковых и корабельных званий и нормативное значение последовательности перечисления.

Статус: **PASS**.

### 2.3 Сопоставление пользовательского документа

Выявленное в пользовательском документе дублирование `старшина 2 статьи` не переносится в данные. Нормативная пара фиксируется как:

```text
сержант — старшина 1 статьи
```

Статус: **PASS**.

### 2.4 Отсутствие корабельного эквивалента

`Маршал Российской Федерации` моделируется как войсковое звание с `naval_name = NULL`.

Статус: **PASS**.

## 3. Architecture review

### 3.1 Версионирование

Версионирование каталога целиком сохраняет исторические редакции и предотвращает смешивание строк разных нормативных состояний.

Статус: **PASS**.

### 3.2 Общий реестр источников

`legal_sources` является повторно используемой сущностью и не привязывает нормативные документы только к одному справочнику.

Статус: **PASS**.

### 3.3 Иерархия составов

Родительский состав `Офицеры` и три дочерних состава отражают нормативную структуру без дублирования каждого звания.

Статус: **PASS**.

### 3.4 Целостность версии

Композитные внешние ключи состава и уровня должны гарантировать, что связанные записи принадлежат одной версии каталога.

Статус: **PASS**.

### 3.5 Read-only boundary

Отсутствие mutation routes, сервисов изменения и форм соответствует нормативному характеру справочника v1.

Статус: **PASS**.

## 4. Database review

Проверены:

- нумерация migration `007` после существующей `006`;
- InnoDB и `utf8mb4_unicode_ci`;
- уникальные коды;
- нормативный `sort_order`;
- nullable корабельное наименование;
- `created_by` с `ON DELETE SET NULL`;
- отсутствие изменений permissions и ролей;
- идемпотентность повторного запуска installer за счёт существующего migration registry.

Статус: **PASS**.

## 5. Repository review

`MilitaryRankCatalogRepository` ограничивается чтением и должен:

- использовать prepared statements;
- не принимать произвольные SQL-фрагменты;
- валидировать фильтр по фактически существующим кодам составов;
- искать через безопасные параметры;
- всегда сортировать по нормативному порядку;
- включать дочерние составы при выборе `Офицеры`.

Статус: **PASS**.

## 6. RBAC / security review

- owner-only boundary использует `require_permission('system.*.*')`;
- не-владелец получает существующую тематическую HTTP 403;
- GET-фильтры не изменяют данные и не требуют CSRF;
- длина поиска ограничивается 150 символами;
- все значения экранируются через `e()`;
- внешние ссылки получают `rel="noopener noreferrer"`;
- новые permissions отсутствуют;
- permission count остаётся 19.

Статус: **PASS**.

## 7. UI review

### 7.1 Навигация

Маршрут сохраняет принятую иерархию:

```text
Контент → Справочники → Составы военнослужащих и воинские звания
```

Статус: **PASS**.

### 7.2 Плитка

Переименование и активация плитки выполняются без изменения плитки `Подразделения`. Используется принятый контракт `Открыть →` и hover обеих тем.

Статус: **PASS**.

### 7.3 Таблица

Четыре колонки достаточны для v1. Нормативный номер выводится явно, корабельное отсутствие обозначается `—`.

Статус: **PASS**.

### 7.4 Источники

Две карточки источников и дата проверки позволяют пользователю отличить нормативные данные от обычного редактируемого справочника.

Статус: **PASS**.

## 8. Scope review

Из scope исключены кадровые процессы присвоения, сроки, история военнослужащего, модификаторы полного наименования и UI-редактирование. Это предотвращает преждевременное объединение нормативного каталога с кадровой моделью.

Статус: **PASS**.
