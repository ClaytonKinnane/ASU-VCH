## Цель

Реализовать защищённый операционный реестр фактической организационной структуры конкретной воинской части. Уполномоченные пользователи формируют структуру вручную в виде дерева на основании утверждённого штата и организационно-распорядительных документов.

## Защита и данные

АСУ-ВЧ эксплуатируется внутри защищённого технического контура. Решение о допуске человека к сведениям принимается вне приложения. Система обеспечивает аутентификацию, RBAC, CSRF, предметные инварианты и историю изменений.

Фактические данные допускаются в рабочей базе защищённой установки, но не включаются в GitHub, migrations, seed, checker, документацию разработки и публичные скриншоты. Автоматические проверки используют только синтетические данные и выполняются с полным rollback.

## Архитектурное решение

```text
OrganizationalStructure
└── OrganizationalStructureVersion
    ├── OrganizationalStructureNode
    └── OrganizationalStructureVersionDocument

OrganizationalStructureElement — стабильная идентичность элемента между версиями.
```

Применяется adjacency list. Родительская связь означает штатное включение и основную постоянную подчинённость. Временные, оперативные и функциональные отношения в v1 отсутствуют.

Существующий справочник типов остаётся read-only классификатором. В типы не добавляется `parent_id`. Каждая версия структуры закрепляет конкретную версию каталога типов.

## Агрегаты

### OrganizationalStructure

Корень — `organizational_structures`.

Отвечает за создание и изменение административной карточки контейнера, архивирование, восстановление и создание новой версии.

### OrganizationalStructureVersion

Корень — `organizational_structure_versions`.

Дочерние сущности — узлы и связи документов. Любое изменение дерева направляется через версию и выполняется транзакционно.

## Жизненный цикл

```text
draft → approved → active → superseded
draft → cancelled
approved → cancelled
```

Одновременно существует не более одной незавершённой версии (`draft` или `approved`) и не более одной `active`. Содержимое версии после выхода из `draft` неизменяемо. Lifecycle-поля изменяются только специализированными командами. Новый черновик копирует действующую версию, а при её отсутствии — последнюю отменённую версию, что исключает блокировку структуры после отмены первоначального черновика.

Периоды действия полуоткрытые: `[effective_from, effective_to)`.

## Инварианты дерева

1. У публикуемой версии ровно один корень.
2. Корень представляет воинскую часть и имеет тип класса `military-unit`.
3. Корень нельзя удалить или переместить.
4. Все остальные узлы имеют одного родителя.
5. Родитель и потомок принадлежат одной структуре и версии.
6. Self-parent и циклы запрещены.
7. Перемещение в собственное поддерево запрещено.
8. Один стабильный элемент встречается не более одного раза в версии.
9. Тип принадлежит закреплённой версии каталога.
10. Порядок соседей уникален.
11. Удаление поддерева требует отдельного подтверждения и основания.

Критические правила дублируются в доменном сервисе и DB constraints/triggers.

## Документы-основания

Хранятся реквизиты без файлов. Роли:

```text
primary_basis
additional_basis
amendment
```

Утверждение требует ровно один `primary_basis`. Реквизиты документа, уже использованного опубликованной версией, изменяются в новом черновике по copy-on-write: опубликованная запись сохраняется, а черновик получает новую запись документа.

## RBAC

```text
organization.structures.view
organization.structures.create
organization.structures.update
organization.structures.publish
organization.structures.archive
organization.structures.history
```

Новые permissions не назначаются автоматически ролям `administrator`, `operator`, `viewer`. Владелец имеет доступ через `system.*.*`. Остальным пользователям доступ предоставляется явным назначением permissions через роли.

## Конкуренция

Mutation-команды соблюдают единый порядок блокировок `OrganizationalStructure → OrganizationalStructureVersion → дочерние записи`, используют `SELECT ... FOR UPDATE` и проверяют `expected_revision`. После каждого изменения черновика `revision` увеличивается. Stale-команды отклоняются.

## UI

Раздел `Контент` становится permission-aware. Модуль включает список структур, карточку, дерево, версии, документы, сравнение и историю. Drag-and-drop не обязателен; доступны кнопки перемещения и изменения порядка.

Поддерживаются три темы и адаптивный mobile-интерфейс. `Mobile PASS` фиксируется только после фактической проверки.

## Вне v1

Военнослужащие, должности, назначения, численность, вооружение, имущество, дислокация, файлы документов, OCR, импорт/экспорт, печатные формы, реальные шаблоны, иные виды подчинённости, индивидуальный ACL структуры, внешний API и общий Audit.
