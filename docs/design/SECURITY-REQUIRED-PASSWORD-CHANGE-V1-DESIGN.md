# SECURITY REQUIRED PASSWORD CHANGE V1 — DESIGN

Статус: Approved for implementation
Дата: 2026-07-25
Ветка: `feature/required-password-change`
Основание: утвержденные пользователем Architecture/Specification в рабочем диалоге проекта.

## 1. Назначение

Инкремент обеспечивает обязательную самостоятельную смену пароля пользователем, если в его учетной записи установлен флаг:

```text
must_change_password = 1
```

До успешного завершения операции пользователь остается аутентифицированным, но не получает доступ к административным разделам системы.

## 2. Текущее состояние

- поле `must_change_password` уже существует в `users`;
- `current_user()` загружает этот флаг из БД при каждом новом HTTP-запросе;
- после успешного входа система всегда перенаправляет в `/admin/`;
- административная панель показывает предупреждение, но не ограничивает маршруты;
- миграция для реализации принудительного flow не требуется.

## 3. Область инкремента

Входят:

- обязательный redirect после входа при `must_change_password = 1`;
- центральная защита всех административных GET/POST-маршрутов;
- страница обязательной смены пароля;
- проверка текущего пароля;
- политика нового пароля;
- транзакционное изменение `password_hash`;
- снятие `must_change_password` и `is_temporary`;
- регенерация сессии и CSRF-контекста;
- адаптивный интерфейс в теме `asu-blue`;
- автоматизированная проверка сервиса.

Не входят:

- добровольная смена пароля при снятом флаге;
- административный сброс пароля;
- восстановление забытого пароля;
- email-уведомления;
- история паролей;
- завершение других сессий;
- MFA;
- срок действия пароля.

## 4. Маршруты

```text
GET  /account/change-password.php
POST /account/change-password.php
```

Один PHP-маршрут отображает форму и обрабатывает POST. Операция относится к собственной учетной записи и не требует отдельного RBAC-разрешения.

## 5. Центральная защита маршрутов

В `app/bootstrap.php` добавляется:

```php
require_authenticated_user(bool $allowRequiredPasswordChange = false): array
```

Алгоритм:

1. загрузить текущего пользователя;
2. при отсутствии пользователя выполнить redirect `/`;
3. при `must_change_password = 1` и отсутствии разрешенного исключения выполнить redirect `/account/change-password.php`;
4. вернуть актуальную запись пользователя.

`require_permission()` и `require_system_owner()` обязаны использовать эту функцию до проверки ролей/разрешений.

`/admin/index.php`, где сейчас используется собственная проверка `current_user()`, также переводится на центральный guard.

Защита должна распространяться на прямой доступ к GET-страницам и POST-операциям, включая управление пользователями.

## 6. Поведение входа

`public/login.php` дополнительно загружает `must_change_password`.

После успешной проверки учетных данных:

```text
must_change_password = 1 → /account/change-password.php
must_change_password = 0 → /admin/
```

`last_login_at` обновляется после успешной аутентификации независимо от обязательного redirect.

## 7. Поведение публичной главной страницы

Для уже авторизованного пользователя:

```text
must_change_password = 1 → /account/change-password.php
must_change_password = 0 → /admin/
```

Неавторизованный пользователь продолжает видеть форму входа/регистрации согласно текущему состоянию установки.

## 8. Сервис

Новый класс:

```text
app/Security/RequiredPasswordChangeService.php
```

Ответственность:

- серверная валидация полей;
- транзакция;
- загрузка пользователя с `FOR UPDATE`;
- проверка active/approved/not deleted;
- `password_verify` текущего пароля;
- проверка нового пароля;
- запрет повторного использования текущего пароля;
- создание нового хэша;
- обновление флагов и времени.

Сервис не работает с HTML, redirect и сессией.

### 8.1 Входные данные

```text
current_password
new_password
new_password_confirmation
```

### 8.2 Успешное обновление

```text
password_hash = password_hash(new password, PASSWORD_DEFAULT)
must_change_password = 0
is_temporary = 0
updated_at = server time
```

### 8.3 Транзакционность

Пользователь загружается внутри транзакции с `SELECT ... FOR UPDATE`. Любая ошибка откатывает транзакцию. После успешного commit маршрут обновляет сессионный контекст.

## 9. Политика пароля

Новый пароль:

- 10–128 байт;
- минимум одна Unicode-буква;
- минимум одна цифра;
- совпадает с подтверждением;
- отличается от текущего пароля.

Пароли не обрезаются через `trim()`.

## 10. Сессионная безопасность

После успешной смены:

1. `session_regenerate_id(true)`;
2. удаление текущего `csrf_token`;
3. создание нового CSRF-токена на следующем запросе;
4. flash-сообщение об успешной смене;
5. redirect `/admin/`.

`user_id` сохраняется. Повторная аутентификация новым паролем непосредственно в этой операции не требуется.

## 11. Страница смены пароля

Форма содержит:

- текущий пароль;
- новый пароль;
- повтор нового пароля;
- кнопку сохранения;
- отдельную POST-кнопку выхода.

Требования:

- все пароли имеют `type=password`;
- отсутствуют `value` с введенными паролями;
- `autocomplete=current-password/new-password`;
- кнопки показать/скрыть;
- CSRF;
- redirect-after-POST;
- темная тема и адаптивность 360/390 px;
- отсутствие горизонтального переполнения.

## 12. Поведение доступа

### 12.1 Пользователь с обязательной сменой

```text
/account/change-password.php → разрешено
/logout.php                  → разрешено
/admin/*                     → redirect на change-password
/                            → redirect на change-password
```

### 12.2 Пользователь без обязательной смены

```text
/account/change-password.php → redirect /admin/
```

### 12.3 Неавторизованный пользователь

```text
/account/change-password.php → redirect /
```

## 13. Ошибки

Поддерживаются ошибки:

- текущий пароль не указан;
- текущий пароль неверен;
- новый пароль не соответствует политике;
- новый пароль совпадает с текущим;
- подтверждение не совпадает;
- учетная запись недоступна;
- серверная операция не выполнена.

Парольные значения не сохраняются в session/flash, URL и HTML.

## 14. База данных

Новая миграция не создается. Используются существующие поля:

```text
password_hash
is_temporary
must_change_password
updated_at
```

## 15. Тестирование

Добавляется:

```text
database/check-security-required-password-change.php
```

Проверки сервиса:

- неверный текущий пароль;
- слабый новый пароль;
- несовпадающее подтверждение;
- повтор текущего пароля;
- успешная смена;
- старый пароль больше не проходит;
- новый пароль проходит;
- оба флага сняты.

Регрессия:

- PHP syntax;
- install/migrations;
- RBAC check;
- approval check;
- local smoke;
- ручные сценарии redirect, logout, CSRF, active-session enforcement и responsive UI.

## 16. Критерии приемки

1. Пользователь с `must_change_password = 1` после входа попадает только на обязательную форму.
2. Прямой доступ ко всем `/admin/*` блокируется центральным guard.
3. Logout остается доступен.
4. Текущий пароль проверяется.
5. Новый пароль соответствует общей политике и отличается от текущего.
6. После успеха старый пароль недействителен, новый действителен.
7. `must_change_password` и `is_temporary` равны `0`.
8. Сессия и CSRF-контекст регенерированы.
9. Активная сессия ограничивается на следующем запросе, если администратор установил флаг.
10. Desktop/mobile интерфейс соответствует теме.
11. Существующие проверки проходят без регрессии.
