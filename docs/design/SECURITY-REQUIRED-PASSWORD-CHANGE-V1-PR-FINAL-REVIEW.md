## 4. Безопасность

Проверено:

- пользователь аутентифицируется до обязательной смены, но не получает доступ к административным разделам;
- guard срабатывает до RBAC и одинаково применяется к владельцу и другим ролям;
- прямые административные маршруты не обходят требование;
- изменяющие административные POST-маршруты используют ту же цепочку guard через `require_permission()` или `require_system_owner()`;
- операция смены пароля требует POST и корректный CSRF-токен;
- текущий пароль проверяется через `password_verify()`;
- новый пароль не сохраняется в session/flash/URL/HTML;
- новый пароль не может совпадать с текущим;
- пароль сохраняется только как результат `password_hash()`;
- строка пользователя блокируется `FOR UPDATE`;
- обновление выполняется транзакционно;
- после успеха регенерируется session ID и CSRF-контекст;
- старый пароль после смены отклоняется;
- новый пароль принимается.

## 6. Маршрутизация

Проверены сценарии:

- login при `must_change_password = 1` ведет на `/account/change-password.php`;
- `/` для уже авторизованного пользователя учитывает обязательную смену;
- `/admin/`, `/admin/users.php`, `/admin/settings.php`, `/admin/content.php` не позволяют обход;
- пользователь без требования смены не остается на обязательной форме;
- выход доступен;
- установка флага во время активной сессии срабатывает на следующем запросе.
