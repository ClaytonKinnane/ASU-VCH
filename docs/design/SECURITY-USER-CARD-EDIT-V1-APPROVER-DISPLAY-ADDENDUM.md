# SECURITY USER CARD EDIT V1 — APPROVER DISPLAY ADDENDUM

Статус: Approved for implementation
Дата: 2026-07-25
Ветка: `feature/initial-site`
Ревизия: 2

## 1. Назначение

Дополнение уточняет отображение сведений о подтверждении пользователя в карточке `/admin/users/view.php?id=<id>`.

## 2. Изменение интерфейса

В блоке «Доступ» не создается отдельное поле `Кем подтвержден`.

Сведения о результате и субъекте действия объединяются в существующем поле `Подтверждение`:

- первая строка — локализованный статус;
- вторая строка — отображаемое имя пользователя, выполнившего подтверждение;
- отображаемое имя является ссылкой на карточку подтверждающего пользователя;
- логин подтверждающего в этом поле не выводится.

Значение формируется только из уже существующих данных миграции 003:

- `approved_by`;
- связанная учетная запись подтверждающего пользователя;
- `approval_status`.

## 3. Правила отображения

- если `approval_status = approved` и подтверждающий пользователь найден, выводится статус `Подтвержден`, а под ним — ссылка с отображаемым именем на `/admin/users/view.php?id=<approved_by>`;
- если `approval_status = approved`, но `approved_by IS NULL`, под статусом выводится текст `Системная операция` без ссылки;
- если `approval_status = pending`, выводится только `Ожидает подтверждения` без второй строки;
- если `approval_status = rejected`, выводится `Отклонен`; сведения об отклонившем не выводятся до реализации отдельного аудита отклонения;
- объединенное поле доступно только владельцу системы и администратору в составе чувствительной части карточки;
- существующий блок «Аудит» сохраняется и продолжает отображать подробные сведения о подтверждении.

## 4. Будущее отображение отклонения

После реализации `Security User Rejection Audit v1` то же поле `Подтверждение` должно поддерживать представление:

- первая строка — `Отклонен`;
- вторая строка — отображаемое имя отклонившего как ссылка на его карточку.

До появления `rejected_by` и `rejected_at` запрещено использовать `approved_by` как сведения об отклонившем.

## 5. Границы дополнения

Не входят:

- операция отклонения пользователя;
- `rejected_by`;
- `rejected_at`;
- основание отклонения;
- маршрут отклонения;
- изменение схемы базы данных.

Полноценный аудит отклонения оформляется отдельным инкрементом `Security User Rejection Audit v1`.

## 6. Безопасность

- новые данные из БД не запрашиваются: используются уже загруженные сведения карточки;
- viewer и operator не получают статус подтверждения и сведения о подтверждающем в HTML;
- отображаемое имя и URL формируются только из серверных данных и экранируются;
- изменение не добавляет POST-операций и не изменяет модель разрешений.

## 7. Критерии приемки

1. Отдельное поле `Кем подтвержден` отсутствует.
2. Для подтвержденного пользователя в поле `Подтверждение` отображается статус и под ним ссылка с отображаемым именем подтвердившего.
3. Логин подтвердившего в поле `Подтверждение` не отображается.
4. Для системного подтверждения под статусом отображается `Системная операция` без ссылки.
5. Для pending-пользователя отображается только `Ожидает подтверждения`.
6. Для rejected-пользователя отображается только `Отклонен` до реализации аудита отклонения.
7. Viewer/operator не получают поле в HTML.
8. Блок «Аудит» продолжает отображаться.
9. PHP syntax check проходит.
10. Desktop и mobile отображение не нарушено.
