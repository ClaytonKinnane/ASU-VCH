# SECURITY USER CARD EDIT V1 — APPROVER DISPLAY ADDENDUM

Статус: Approved for implementation
Дата: 2026-07-25
Ветка: `feature/initial-site`

## 1. Назначение

Дополнение уточняет отображение сведений о подтверждении пользователя в карточке `/admin/users/view.php?id=<id>`.

## 2. Изменение интерфейса

В блоке «Доступ» рядом со статусом подтверждения добавляется поле:

- `Кем подтвержден`.

Значение формируется только из уже существующих данных миграции 003:

- `approved_by`;
- связанная учетная запись подтверждающего пользователя;
- `approval_status`.

## 3. Правила отображения

- если `approval_status = approved` и подтверждающий пользователь найден, выводятся его отображаемое имя и логин;
- если `approval_status = approved`, но `approved_by IS NULL`, выводится `Системная операция`;
- если пользователь еще не подтвержден, выводится `Не подтвержден`;
- поле доступно только владельцу системы и администратору в составе чувствительной части карточки;
- существующий блок «Аудит» сохраняется без удаления или изменения данных.

## 4. Границы дополнения

Не входят:

- отклонение пользователя;
- `rejected_by`;
- `rejected_at`;
- основание отклонения;
- маршрут отклонения;
- изменение схемы базы данных.

Полноценный аудит отклонения оформляется отдельным инкрементом `Security User Rejection Audit v1`.

## 5. Безопасность

- новые данные из БД не запрашиваются: используются уже загруженные сведения карточки;
- viewer и operator не получают поле и его значение в HTML;
- все значения экранируются существующей функцией `e()`;
- изменение не добавляет POST-операций и не изменяет модель разрешений.

## 6. Критерии приемки

1. Для подтвержденного пользователя отображается имя и логин подтвердившего.
2. Для системного подтверждения отображается `Системная операция`.
3. Для pending-пользователя отображается `Не подтвержден`.
4. Viewer/operator не получают поле в HTML.
5. Блок «Аудит» продолжает отображаться без изменений.
6. PHP syntax check проходит.
7. Desktop и mobile отображение не нарушено.
