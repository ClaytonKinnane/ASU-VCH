# SECURITY USER CARD EDIT V1 — APPROVER DISPLAY REVIEW

Статус: Reviewed
Дата: 2026-07-25
Ревизия: 2

## Проверено

- изменение не требует миграции;
- `approved_by` и отображаемое имя подтверждающего уже доступны в `UserDetailRepository`;
- сведения можно вывести внутри существующего поля `Подтверждение` без отдельной плитки;
- ссылка может безопасно вести на существующий маршрут `/admin/users/view.php?id=<id>`;
- логин подтверждающего для компактного представления не требуется;
- чувствительное поле остается внутри проверки `includeSensitive`;
- viewer/operator не получают статус подтверждения и сведения о подтверждающем;
- вывод не влияет на операции создания, подтверждения, блокировки и изменения ролей;
- существующий блок аудита сохраняется;
- данные отклонения не моделируются через `approved_by`.

## Решение review

Дополнение допустимо к реализации в текущем инкременте как уточнение представления существующих аудитных данных.

Статус подтверждения и отображаемое имя субъекта действия должны находиться в одном поле. Отдельное поле `Кем подтвержден` подлежит удалению.

Аудит отклонения должен проектироваться отдельно с собственными полями, миграцией и действием отклонения. После его реализации имя отклонившего может отображаться второй строкой того же поля `Подтверждение`.
