# Домен Reference

## 1. Статус документа

Статус: `APPROVED`

Документ определяет границы, ответственность, сущности, бизнес-правила, сервисы, события и варианты использования домена `Reference`.

Домен является единым источником нормативно-справочных данных для остальных доменов системы.

## 2. Назначение

`Reference` предоставляет централизованное хранение, получение и сопровождение справочных данных.

Домен не содержит прикладной бизнес-логики других предметных областей и не принимает решений за домены-потребители.

## 3. Ответственность

Домен отвечает за:

- группы справочников;
- значения справочников;
- машинные коды групп и значений;
- отображаемые наименования и описания;
- порядок сортировки;
- значения по умолчанию;
- системные группы и значения;
- поиск групп и значений;
- получение значений по `id` и `code`;
- публикацию событий об изменениях;
- передачу событий изменений в Audit.

## 4. Что не входит в ответственность

Домен не отвечает за:

- пользователей и роли;
- военнослужащих;
- подразделения и воинские части;
- документы;
- медицинские данные;
- имущество и транспорт;
- авторизацию;
- вычисления и прикладные процессы;
- бизнес-валидацию доменов-потребителей.

## 5. Сущности

### 5.1 reference_groups

Группа объединяет значения одного справочника.

Предварительный состав полей:

```text
id
code
name
description
is_system
created_at
updated_at
deleted_at
```

### 5.2 reference_values

Значение принадлежит ровно одной группе справочника.

Предварительный состав полей:

```text
id
group_id
code
name
description
sort_order
is_default
is_system
created_at
updated_at
deleted_at
```

## 6. Бизнес-правила

### 6.1 Уникальность групп

`reference_groups.code` уникален глобально.

Код группы не переиспользуется после soft delete.

### 6.2 Уникальность значений

`reference_values.code` уникален в пределах одной группы.

Допускается использование одинакового кода в разных группах:

```text
user_status.active
equipment_status.active
transport_status.active
```

### 6.3 Неизменяемость машинных кодов

После публикации машинные коды групп и значений не изменяются.

Для замены семантики создается новая группа или новое значение, а старое выводится из использования в контролируемом порядке.

### 6.4 Нормализация кодов

Коды:

- обрезаются по краям;
- приводятся к нижнему регистру;
- хранятся в ASCII;
- используют формат `snake_case`;
- не содержат локализованный пользовательский текст.

### 6.5 Отображаемые наименования

Поле `name` допускается изменять без изменения машинного контракта, если изменение не нарушает нормативные требования и не меняет смысл значения.

### 6.6 Системные данные

Группы и значения с `is_system = true`:

- не удаляются пользователем;
- не допускают изменения машинного кода;
- создаются и обновляются только через утвержденные seeders, migrations либо системный административный процесс;
- защищаются доменным сервисом.

### 6.7 Soft delete

Для групп и значений применяется soft delete.

Удаленная запись не считается активной и не должна возвращаться стандартными lookup-операциями.

### 6.8 Ссылки из других доменов

Другие домены хранят внешние ключи на `reference_values.id`.

`code` используется для:

- поиска;
- сидирования;
- конфигурации;
- стабильного программного контракта.

Внешние ключи по `code` не создаются.

### 6.9 Удаление используемых данных

Группа или значение не могут быть удалены, если это нарушит ссылочную целостность или действующие бизнес-процессы.

Ограничение обеспечивается доменным сервисом и внешними ключами с политикой `RESTRICT`.

### 6.10 Значение по умолчанию

В пределах группы может существовать не более одного активного значения с `is_default = true`.

Наличие значения по умолчанию не является обязательным для каждой группы.

### 6.11 Порядок сортировки

`sort_order` определяет стабильный прикладной порядок отображения.

Значение `id` не используется как бизнес-порядок сортировки.

## 7. Сервисы

### 7.1 ReferenceGroupService

Отвечает за:

- создание и изменение групп;
- проверку уникальности кода;
- защиту системных групп;
- soft delete групп;
- проверку допустимости удаления.

### 7.2 ReferenceValueService

Отвечает за:

- создание и изменение значений;
- проверку уникальности кода внутри группы;
- управление `sort_order`;
- управление значением по умолчанию;
- защиту системных значений;
- soft delete значений.

### 7.3 ReferenceLookupService

Предоставляет операции чтения:

- найти группу по `id`;
- найти группу по `code`;
- найти значение по `id`;
- найти значение по паре `group.code + value.code`;
- получить активные значения группы;
- получить значение группы по умолчанию.

Lookup-сервис не изменяет данные.

## 8. Репозитории

```text
ReferenceGroupRepository
ReferenceValueRepository
```

Репозитории отвечают за сохранение и выборку, но не содержат бизнес-правила домена.

## 9. Доменные события

Минимальный набор событий:

```text
ReferenceGroupCreated
ReferenceGroupUpdated
ReferenceGroupDeleted
ReferenceValueCreated
ReferenceValueUpdated
ReferenceValueDeleted
ReferenceDefaultValueChanged
```

События должны содержать идентификатор инициатора либо идентифицированный системный источник.

## 10. Варианты использования

### Управление группами

- создать группу;
- изменить наименование и описание группы;
- получить группу;
- получить список групп;
- удалить пользовательскую группу;
- восстановить группу в отдельном утвержденном сценарии.

### Управление значениями

- добавить значение в группу;
- изменить наименование, описание и порядок;
- установить значение по умолчанию;
- получить значение;
- получить список активных значений группы;
- удалить пользовательское значение;
- восстановить значение в отдельном утвержденном сценарии.

### Системное сопровождение

- идемпотентно создать системные группы;
- идемпотентно создать системные значения;
- проверить наличие обязательных системных кодов;
- передать изменения в Audit.

## 11. Зависимости

Допустимые зависимости:

```text
Reference → Infrastructure
Reference → Audit contract
```

Ссылка на Audit означает публикацию событий через абстракцию и не создает зависимости доменной модели Reference от реализации Audit.

## 12. Запрещенные зависимости

Домен не должен зависеть от:

```text
Security
Organization
Personnel
Documents
Medical
Equipment
Transport
Orders
```

Домены-потребители могут зависеть от публичных контрактов `Reference`.

## 13. Решения первой версии

В первой версии не реализуются:

- иерархические справочники и `parent_id`;
- произвольные JSON-атрибуты;
- пользовательские схемы метаданных;
- версии справочников;
- периоды действия `valid_from` / `valid_to`;
- локализация значений отдельными таблицами;
- автоматическая синхронизация с внешними классификаторами;
- массовый импорт через UI.

Эти возможности могут быть добавлены только после подтвержденной бизнес-потребности и архитектурного ревью.

## 14. Инварианты

- активная группа имеет уникальный `code`;
- активное значение имеет уникальный `code` внутри группы;
- значение всегда принадлежит существующей группе;
- машинный код опубликованной записи неизменяем;
- системные записи не удаляются пользовательскими операциями;
- в группе не более одного активного значения по умолчанию;
- удаление не нарушает ссылочную целостность;
- чтение по умолчанию не возвращает soft-deleted записи.

## 15. Требования к аудиту

Аудируются:

- создание группы;
- изменение группы;
- удаление и восстановление группы;
- создание значения;
- изменение значения;
- удаление и восстановление значения;
- изменение значения по умолчанию;
- попытки изменения защищенных системных данных.
