# Спецификации миграций АСУ-ВЧ

## 1. Назначение

Каталог `docs/migrations` содержит физические спецификации миграций базы данных по доменам АСУ-ВЧ.

Документ миграций является обязательным промежуточным артефактом между ERD и программной реализацией:

```text
ERD
  ↓
Migration Specification
  ↓
Database Migrations
  ↓
Seeders and Installation Commands
```

Миграции и сидеры не создаются до утверждения соответствующей спецификации.

## 2. Ответственность спецификации

Каждая спецификация должна фиксировать:

- порядок создания и удаления объектов;
- точные типы колонок;
- nullable/default-правила;
- первичные, внешние и уникальные ключи;
- имена индексов и ограничений;
- generated columns;
- триггеры целостности;
- системные seed-данные;
- первичную установку;
- проверки после миграции;
- стратегию отката;
- зависимости от других доменов.

## 3. Границы

Спецификация миграций не должна:

- заменять ERD;
- вводить новые сущности без изменения ERD;
- скрыто изменять бизнес-правила;
- реализовывать бизнес-логику в триггерах;
- создавать первого владельца системы как статические исходные данные;
- хранить пароли, токены или иные секреты в открытом виде.

## 4. Именование

Файлы спецификаций:

```text
SECURITY-MIGRATIONS.md
REFERENCE-MIGRATIONS.md
ORGANIZATION-MIGRATIONS.md
AUDIT-MIGRATIONS.md
```

Миграции именуются по выполняемому действию, например:

```text
CreateUsersTable
CreateUserRolesTable
AddActiveRoleIdToUserRolesTable
CreateUsersStatusValidationTriggers
```

Имена ключей и индексов должны быть явными и стабильными.

## 5. Правила выполнения

- Все таблицы используют InnoDB.
- Основная кодировка — `utf8mb4`.
- MySQL `ENUM` не используется.
- Рабочие сущности не удаляются каскадно.
- Критические изменения выполняются транзакционно, где это поддерживается СУБД.
- Seeder должен быть идемпотентным и работать по неизменяемым кодам.
- Установка первого владельца выполняется отдельной защищенной командой.
- После каждой миграции выполняются автоматические проверки структуры и ограничений.

## 6. Порядок разработки

```text
Domain Specification
        ↓
ERD
        ↓
ERD Review
        ↓
Migration Specification
        ↓
Migration Review
        ↓
Migrations and Seeders
        ↓
Integration Tests
```

Отклонение от утвержденной спецификации сначала отражается в документации и проходит ревью.
